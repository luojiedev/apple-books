# Apple Books 数据挖掘与功能建议

核查日期：2026-09-16。使用 `sqlite3 -readonly` 检查本机 Apple Books 的实时数据库（包含可见的 WAL 数据），而非项目内 9 月 4 日的快照。以下数字是本机当前样本，不代表所有用户或 Apple 的公开接口保证；没有修改源数据库。

建议第一批实现“摘录上下文展开 + 继续阅读工作台”。两项可复用现有数据源，无需增加私有格式解析，分别改善笔记回顾和下一步阅读决策。

## 数据质量对功能的限制

- 书库共 1,460 条记录，不应不加区分地等同于 1,460 本独立电子书：包含多种内容类型、重复版本及系列相关数据。
- 页数大于零的仅 90 条（约 6.2%）；不适合普遍计算剩余页数、每小时页数或预计读完时间。
- 分类非空 319 条（约 21.8%），语言非空 74 条（约 5.1%）；阅读偏好分析必须显示“未知”和覆盖率。
- 179 条记录有系列 ID，可探索系列分组，但须先核对系列容器、成员关系和顺序字段。
- 65 条记录的最远进度比当前进度高至少约一个百分点；可展示“当前 / 最远”，不能据此认定重读次数。
- 1,264 条有路径、1,264 条有正文件大小；非空路径不证明文件存在、已下载或可打开。书库健康检查需要额外只读验证文件。
- 本机书库评分大于零的记录为 0，不适合以评分作为当前推荐依据。
- 已有 ReadingHistoryModel 适合年度/月度总时长；本次没有发现可直接替代它的可靠单书时长数据。

## 实施要求

1. 继续只读 Apple 数据；新增复习状态或进度快照时单独持久化，以稳定 ID 和唯一约束保证重复刷新、导出或采样的幂等性。
2. 对新增来源先核验字段及版本；如需兼容其他版本，先确认兼容范围。
3. 新增业务逻辑提供 Debug / Error 日志，避免将笔记正文写入日志。
4. 上下文文本按普通文本安全呈现；导出上下文应由用户选择，保留原划线和笔记的区分。
5. 验证上下文相同、缺失、不包含选中文字，重复书名不同 asset ID，空书单、删除成员、未知日期与进度等边界。

本次完成数据调研与功能优先级判断，未修改应用代码，也未运行编译或测试。
